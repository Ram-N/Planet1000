# New Puzzle Creation Workflow

Step-by-step guide for creating a new Planet 1000 weekly puzzle from scratch.

---

## Overview

Every puzzle requires three things:
1. A **slim manifest** (`data/puzzles/<id>.json`) — question, observation, explanation
2. **Three facts** in `data/canonical-facts/<domain>.csv` — one relationship, one temporal, one anchor
3. A **knowledge summary** (`data/summaries/summary_<topic>.json`) — post-game learning content

Running `npm run build:puzzles` assembles these into the full puzzle the game reads.

---

## Step 1 — Scaffold the manifest

```bash
npm run puzzle -- new 2026-W37
```

The script lists available observations, prompts for domain, `observation_id`, and question, then writes `data/puzzles/puzzle_2026_w37.json`.

Open the file and fill in `answer_explanation` — a 2–3 sentence plain-English explanation of what the answer means (written as if the player just learned the number for the first time).

Also set `summary_id` to the summary you will create in Step 4, e.g. `"summary_id": "summary_<topic>"`.

---

## Step 2 — Add facts to `data/canonical-facts/<domain>.csv`

Open the domain file for the observation (e.g. `data/canonical-facts/housing.csv`) and add three rows, one of each type. The domain matches `entity.domain` in `world-model.json` — use `npm run fact-hunt -- hunt <obs-id>` if unsure which file to edit. Alternatively, use the interactive tool which routes automatically:

| Column | What to write |
|--------|---------------|
| `observation_id` | Must exactly match the manifest's `observation_id` |
| `type` | `relationship`, `temporal`, or `anchor` |
| `text` | The fact shown to the player as a hint |
| `source` | Free text, e.g. `WHO https://who.int/data` |
| `year` | Year the data refers to |

**relationship** — how this quantity compares to something else. Should narrow the estimate without revealing it.

**temporal** — how it has changed over time. Should give the player a sense of direction.

**anchor** — a concrete reference point at a similar scale. Should help the player calibrate.

Check nothing is missing:

```bash
npm run fact-hunt -- status
```

---

## Step 3 — Build and preview

```bash
npm run build:puzzles
npm run puzzle -- show puzzle_2026_w37
```

Check:
- Answer value looks right
- All three hints are present
- No hint gives away the answer directly (Hint 2 is the most common culprit)

If a hint is wrong, edit the relevant `data/canonical-facts/<domain>.csv` and rebuild. If the answer value is wrong, check the observation in `world-model.json`.

Use the browser preview for a richer view:

```bash
npm run dev
# navigate to http://localhost:3000/creator/puzzle_2026_w37
```

---

## Step 4 — Create the knowledge summary


This is the piece with which we conclude the puzzle. In it, we can show graphs, 
tables, facts, Sources and Takeaways. These are usually LLM generated + from websites.
Place all source material (screenshots, exported charts, `.txt` data) in:

```
data/source/summary-input/<topic>/
```

Then generate the summary:

```bash
npm run summary -- build summary_<topic>
npm run summary -- validate summary_<topic>
```

The `build` command reads the source folder, calls the Claude API, and writes a structured JSON to `data/summaries/summary_<topic>.json`.

Requires `ANTHROPIC_API_KEY` in the environment.

After generation, open the file and review each section. Edit any text that is off, reorder sections if needed, and verify source URLs are correct.

---

## Step 5 — Rebuild with summary linked

Make sure `summary_id` is set in the manifest, then rebuild:

```bash
npm run build:puzzles
```

This also rewrites `lib/puzzle-loader.ts` automatically — no manual import edits needed.

Verify the summary is linked:

```bash
npm run summary -- status
```

---

## Step 6 — Final check and commit

```bash
npx tsc --noEmit                          # no type errors
npm run puzzle -- status                  # puzzle appears with correct answer
# http://localhost:3000/creator           # dashboard shows "Ready"
# http://localhost:3000/creator/<id>      # all hints, answer, summary ✓
```

Commit everything:

```bash
git add data/puzzles/puzzle_2026_w37.json \
        data/generated/puzzles/puzzle_2026_w37.json \
        data/summaries/summary_<topic>.json \
        "data/canonical-facts/<domain>.csv" \
        lib/puzzle-loader.ts
git commit -m "feat(puzzle): add 2026-W37 puzzle and summary_<topic>"
git push
```

Vercel picks up the push and deploys automatically.

---

## Files touched per puzzle

| File | Action |
|------|--------|
| `data/puzzles/<id>.json` | Created by `puzzle new`, edited manually |
| `data/canonical-facts/<domain>.csv` | 3 rows added — one per fact type |
| `data/summaries/summary_<topic>.json` | Created by `summary build` |
| `data/generated/puzzles/<id>.json` | Generated by `build:puzzles` — commit this |
| `lib/puzzle-loader.ts` | Regenerated by `build:puzzles` — commit this |

---

## Key commands at a glance

```bash
npm run puzzle -- new <week-id>           # scaffold manifest
npm run puzzle -- status                  # list all puzzles
npm run puzzle -- show <id>               # preview resolved puzzle
npm run fact-hunt -- status               # check for missing fact types
npm run build:puzzles                     # generate full puzzles + loader
npm run build:puzzles -- --allow-missing  # build even with missing facts
npm run summary -- build summary_<topic>  # AI-generate summary from sources
npm run summary -- validate summary_<topic>
npm run summary -- status                 # check puzzle↔summary links
```
